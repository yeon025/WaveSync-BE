# 인증·인가

엔드포인트 목록은 [README의 인증·인가 섹션](../README.md#인증인가)을 참고하세요. 이 문서는 각 동작의 상세 규칙을 다룹니다.

로그인·회원가입 없이 사용하는 개인/데모 서비스이므로, 서버가 발급하는 **게스트 세션 쿠키**로 호출자를 식별한다. 모든 캐릭터 데이터는 호출자별로 분리해 관리한다.

## 게스트 세션

- 세션이 없거나 유효하지 않으면 새 게스트 계정과 세션을 발급하고, 유효한 세션이 있으면 기존 계정을 재사용한다.
- 세션은 180일간 유효하며, 만료가 30일 이내로 남으면 자동 연장된다.
- 세션이 만료되거나 폐기되면 기존 데이터를 다시 이용할 수 없으며, 새 게스트 계정으로 서비스를 이용해야 한다.
- 신규 게스트 계정 생성에는 IP 기준 요청 제한을 적용한다.

## Google 로그인

Google 계정을 게스트 세션에 연결해 기기를 변경하거나 쿠키가 삭제되어도 기존 데이터에 다시 접근할 수 있도록 한다.

- Google 인증 후 사용자 정보를 검증하고, Google 계정 식별자를 기준으로 계정을 연결하거나 기존 계정을 불러온다.
- 기존 게스트 계정에 Google 계정을 연결하면 기존 사용자 ID와 데이터를 유지한다.
- 이미 다른 계정에 연결된 Google 계정은 자동으로 병합하지 않으며, 충돌 시 오류를 반환한다.
- 로그인 성공 시 기존 세션을 폐기하고 새 세션을 발급한다.
- Google 액세스 토큰과 리프레시 토큰은 저장하지 않으며, 인증 실패 시 허용된 프런트 주소로 오류 코드를 전달한다.

## 데이터 소유권

`user_resonators.user_id`를 기준으로 캐릭터 데이터의 소유자를 구분한다. 조회·수정·삭제 등 모든 작업은 현재 세션의 사용자 ID를 기준으로 처리하며, 다른 사용자의 데이터에는 접근할 수 없다.

존재하지 않거나 소유자가 다른 캐릭터 데이터는 동일한 오류 응답으로 처리한다. 기존 API 응답 규칙을 유지하기 위해 `RESONATOR_NOT_FOUND`를 사용한다.

## CSRF 방어

프런트엔드와 백엔드가 서로 다른 사이트에서 동작하므로, 쿠키 기반 인증을 보호하기 위해 상태 변경 요청(POST/PATCH/DELETE)에 CSRF 방어를 적용한다.

- `X-WaveSync-Csrf: 1` 헤더를 필수로 요구한다.
- `Origin` 헤더가 있는 경우 허용된 오리진인지 확인한다.
- 허용되지 않은 요청은 `403 FORBIDDEN`으로 거부한다.

## 관리자 권한

관리자 권한은 서버에서 관리하는 세션의 `role`을 기준으로 판단한다.

- 서버 환경변수 `ADMIN_EMAIL`에 등록된 Google 계정은 인증 시 `admin` 역할을 부여받으며, 그 외 계정은 `user` 역할을 부여받는다.
- 관리자 여부는 검증된 Google 계정 정보를 기준으로 서버에서 결정한다.
- Google 로그인 시마다 역할을 다시 확인해 반영하며, 이미 발급된 세션의 역할은 다시 로그인하기 전까지 유지된다.

## 프런트엔드에 필요한 변경 (이 저장소 범위 밖)

- 앱 진입 시 `POST /api/auth/session` 1회 호출(쿠키 자동 저장).
- 백엔드로 보내는 모든 요청에 `credentials: "include"` 추가.
- POST/PATCH/DELETE 요청에 `X-WaveSync-Csrf: 1` 헤더 추가(세션 발급 요청 포함).
